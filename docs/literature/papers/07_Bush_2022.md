## Method as implemented

Two detectors, run separately, both with the same post-processing. Quotes are from STAR Methods, "Identifying Candidate Replay Events", p. e2.

- Setup: "We used two methods to identify candidate replay events – either as periods of elevated multi-unit activity (MUA) or ripple band power."
  - The main text uses MUA: "First, we looked for candidate replay events during REST on the basis of MUA (see STAR Methods for further details).24" (Results, p. 65). Ref 24 is Ólafsdóttir 2017.
  - The ripple method is a control: "Qualitatively similar results were also obtained ... when candidate replay events were identified using ripple band power instead of MUA (Figure S2C ...)" (Results, p. 66).

- MUA detector:
  - "we first generated a MUA histogram for all putative principal cells in 1ms time bins. This histogram was then smoothed using a Gaussian kernel with 5ms standard deviation and candidate replay events identified as periods of Z ≥ 0 with peak Z ≥ 3. Any candidate events separated by ≤ 40ms were merged and any remaining events with a duration of ≤ 40ms discarded. Finally, we excluded any events during which < 5 or 15% of all pyramidal cells were active (whichever is the larger), median running speed > 10cm/s, or duration > 0.5 s."
  - Units, from "Identifying Putative Principal Cells": "All analyses were restricted to putative principal cells, identified by manual inspection of waveforms and mean firing rates ≤ 10Hz across the entire recording session."
  - Whether "all putative principal cells" in the MUA histogram includes the MEC principal cells recorded at the same time is not stated. Inference: CA1 only, since the participation denominator is "all pyramidal cells".
  - The MUA is from sorted units (spike trains), not threshold-crossing multiunit.

- Ripple-band detector (control):
  - "we first identified the EEG channel in each RUN session with the highest 6-12Hz theta signal to noise ratio. Next, we filtered LFP data from that channel in the 150-250Hz ripple band using a 400th order finite impulse response (FIR) filter, extracted the amplitude of the filtered signal using the Hilbert transform and smoothed that time series using a Gaussian kernel with 5ms standard deviation. Candidate replay events were then identified as periods with ripple band amplitude Z ≥ 0 and peak ripple band amplitude Z ≥ 3." It is followed by the same merge, discard, participation, speed and maximum-duration steps.
  - LFP is sampled at 4.8 kHz ("EEG data were concurrently acquired at a sample rate of 4800Hz").

- Order, for both detectors: merge (gap ≤ 40 ms), then discard duration ≤ 40 ms, then participation, median speed and duration > 0.5 s.

- Participation denominator: all pyramidal cells (putative principal cells) in the session, with an absolute floor of 5: active cells ≥ max(5, 15%).

- Normalization period for Z: not stated.

- Brain state: none. REST is 1.5 h in an enclosure. "Online" candidate events at track corners during RUN were analysed with the same detection: "candidate 'online' replay events, which occurred while the animal was awake but immobile at the corners of the track during RUN" (Results, p. 66).

Later analysis steps (not detection):

- Decoding (STAR Methods, "Decoding Location during Replay Events", p. e4): "consecutive time bins of T = 10ms throughout the replay event, starting at the time of the first spike fired by any cell". This aligns the decoding bins, not the event bounds.

- Significant linear replay is judged against shuffles.

- n-spike analyses use cells with ≥ 3 spikes in an event.

## Inherited from

Ólafsdóttir 2017 (ref 24, [paper note](32_Olafsdottir_2017.md)). Bush states every parameter itself, and they differ from that paper (all principal cells rather than place cells, a merge step, median speed ≤ 10 rather than 3, a 0.5 s maximum). No further hop was needed.

## Uncertainties

Later Barry-lab code cannot establish Bush’s original parameters. The raw-data ZIP directory has no separately named SWR/replay/candidate files; not every variable in every MAT file was inspected.

## Package mapping

Packaged primary method: `bush_2022` in [literature_methods.py](../../../src/ripple_detection/literature_methods.py). Its docstring records implementation choices and assumptions. Simulation checks establish that it runs; they do not establish equivalence to the authors’ original event set.

Additional inventories in the same module: `bush_2022_ripples`. See their docstrings for required settings and output stages.

The secondary ripple implementation applies a 400th-order FIR forward and backward,
giving effective order 800 and a squared magnitude response. This zero-phase
application and the Hamming window are implementation choices, not specified
by the paper.
