## Method as implemented

Detection. Paper quotes are from Methods, "Candidate replay event detection" (p. 19). Code quotes are from `Pipeline/Extract replay and Bayesian Decoding/extract_replay_events.m` and neighbours at commit 44ecf42.

- Signal: sorted and unsorted spikes pooled. The paper says only "Candidate replay events were detected based on MUA." The code builds the histogram from single units plus the clusters rated multi-unit: `all_MUA_time= [clusters.spike_times; spike_times_MUA]` (`process_clusters.m`). Clusters rated noise are left out ("The rest of the clustered activity was classified in either multi-unit activity (MUA) or noise", Methods, "Spike detection and unit isolation", p. 18). All tetrodes are pooled (CA1 pyramidal layer).

- Smoothing. Paper: "MUA was first smoothed with a Gaussian kernel (sigma = 5 ms) and binned into 1 ms steps." Code: 1 ms histogram, then `w=gausswin(41,2); w=w./sum(w); %gaussian kernel 10 ms STD, 2 std width`, then `MUA.zscored=zscore(filtfilt(w,1,histcounts(...)))`. gausswin(41, 2) has nominal Gaussian SD (41−1)/(2·2) = 10 samples = 10 ms. After normalization, the finite 41-point kernel has SD 8.898 ms; filtfilt applies it twice, giving effective SD 12.583 ms. The untruncated approximation would be 14.142 ms. **Text and code disagree (5 ms versus this two-pass kernel).**

- Normalization: `zscore` over the whole recording from `min(Time)` to `max(Time)`, so PRE, RUN and POST are all included. The paper does not say.

- Threshold and bounds. Paper: "Only MUA bursts with a maximum duration of 300 ms and z-scored activity over 3 were selected." Code: supra-threshold samples are `mua_zscore>=3`. A new burst starts wherever consecutive supra-threshold samples are ≥10 ms apart: `find(diff([0 time(mua_idx)])>=0.01)`. From the burst's first supra-threshold sample the code searches ±300 samples (300 ms, `max_search_length=300`). Onset is the last sample with z < 0 before it and offset is the first sample with z < 0 after it. If none is found within 300 ms, the bound criterion is relaxed to z ≤ 0.25, then to z ≤ 0.5. After that the event is flagged `error` and the search-window edge is used. So "maximum duration of 300 ms" means this ±300 ms search window, not a filter on duration.

- Minimum duration: "discarded if ... their duration was below 100 ms". In code, `replay.duration < 0.1` removal runs on onset-to-offset **before** merging.

- Merge: "Events detected within 50 ms were combined." In code: `replay.onset(2:end)-replay.offset(1:end-1)<0.05`, repeated until nothing merges. It runs after the minimum-duration cut and before the speed, participation and ripple criteria.

- Maximum duration: the paper says "or over 750 ms". **The code only counts these and keeps them**: `% check for long events (more than 1 second) but leave them` / `number_of_long_events=length(long_events)`. No inspected Tirole script enforces 0.75 s. The related Huelin Gorriz release lacks its event extractor, so this conclusion does not establish that paper’s runtime maximum.

- Speed: "the animal's speed was required to be less than 5 cm/s". Code: `speed = interp1(position.t,position.v_cm,[onset:.01:offset],'nearest'); replay.speed(i) = median(speed)`, with events removed when `replay.speed>5`. This is a median over the event, sampled every 10 ms.

- Participation: "discarded if their sequence had less than five different units active". Code: `replay.neuron_count<5` removed. `neuron_count` counts unique `place_fields.good_place_cells` (cells with a good place field on at least one track) with ≥1 spike in [onset, offset]. The denominator is therefore place cells, an absolute count of 5, not the units that make up the MUA trace.

- Ripple (required, AND): "the ripple-band filtered LFP signal was smoothed with a 0.1 s moving average filter and a threshold over 3 was set for the z-scored ripple power, and used as an additional criterion for candidate replay events." Code, in `extract_CSC.m`:
  - One channel, the one with the highest ripple-band PSD power (`bestCSC_ripple`, `determine_best_channel.m`). Methods, "LFP analysis" (p. 18): "identify the channels with higher power for theta (4–12 Hz) and ripple (125–300 Hz)".
  - Downsampled to 1 kHz (`CSC(jj).SR = 1000`), then `fir1` band-pass 125–300 Hz of order round(6·1000/175) = 34, applied with `filtfilt`.
  - Envelope and smoothing: `CSC(jj).ripple_zscore = zscore(smooth(abs(hilbert(CSC(jj).ripple)),15)')`. That is the Hilbert amplitude, then a **15-sample (15 ms) moving average**, then a z-score over the whole recording. **Text says 0.1 s.**
  - Test: `replay.ripple_peak(i) = max(ripple_zscore(time>onset & time<offset))`, then `find(replay.ripple_peak >= 3)` in `Pipeline/Replay scoring and shuffling/number_of_significant_replays.m`. So the peak ripple z strictly inside the MUA event must be ≥ 3.
  - The Results confirm the ripple is a requirement. A robustness control is described as "not requiring a threshold for ripple power for candidate replay events (Figure 1—figure supplement 6 ...)" (Results, p. 6).

- Brain state: none for detection.

Later analysis steps (not detection):

- Decoding split: "candidate replay events were split in half ... the minimum MUA activity in the middle third of the candidate replay event was used to determine a natural midpoint". This is decoding only.

- Replay classification: awake versus rest ("Replay events detected during sleep or rest periods within the rest pot were classified as rest replay events"). This is analysis, not detection.

- Significance: weighted correlation against three shuffles, with p < 0.05 for whole events and p < 0.025 for halves.

## Inherited from

The code header says "based on Davidson, Kloosterman, and Wilson(2009,Neuron) criteria. - events detected by MUA only - zscore of 3 minimum, and edges detected by zscore of 0". The paper cites nothing for detection. The release specifies the extraction algorithm directly; the Davidson citation was not followed for additional parameters.

## Analysis and interpretation

Whole-event replay must pass all three shuffle tests at p<0.05; a split half must pass all three at p<0.025. Shuffles are 1000 per method.

## Reproduction limits

The method-specific qualifications above apply. The executable recipe documents its assumptions about unstated parameters, state scoring and simulation stand-ins.
