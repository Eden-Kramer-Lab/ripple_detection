## Method as implemented

The detection text is the same as Michon 2019, nearly word for word.

- SWR: "The local field potentials from 1-3 tetrodes were downsampled from 32 kHz to 4 kHz and filtered in the ripple frequency band (140-225 Hz). The ripple envelope was computed as the absolute value of the Hilbert-transformed filtered ripple signal, averaged across the selected tetrodes and smoothed with a Gaussian kernel (bandwidth 15 ms). Slow trends in the ripple envelope were removed using a moving median filter (window length 3 s). Finally, start and end times of ripple events were detected when the detrended ripple envelope exceeded a low threshold of m + 0:53s and the maximum envelope exceeded a high threshold of m + 83 s. Here, m and s represent the mean and standard deviation of the detrended ripple envelope. Ripple events that were separated by less than 20 ms were merged into a single event, and events with a duration shorter than 40 ms were excluded." (STAR Methods "Detection of sharp-wave ripple (SWR) events", p. e2). The rendering is μ + 0.5σ and μ + 8σ.

- Electrodes: "the electrodes were lowered toward the pyramidal cell layer of hippocampal area CA1" (p. e1–e2).

- MUA bursts and candidates: "A smoothed multi-unit activity (mua) rate histogram (5 ms bin size, Gaussian kernel with 15 ms bandwidth) was computed from all unsorted spikes recorded from the hippocampus with a peak amplitude larger than 60 mA [sic; µV]. The rate was detrended using a moving median filter (window length 3 s). Transient bursts in the detrended mua were defined using a double threshold procedure, where the upper threshold m + 43s determines if a burst occurred and the lower threshold m + 0:53s determines burst start and end time. Bursts that were separated by less than 20 ms were merged, and bursts with a duration shorter than 80 ms were excluded. Candidate replay events were defined as mua bursts that overlapped with a ripple event and which occurred while the animal was immobile (run speed < 5 cm/s)." (Replay analysis, p. e4)

- Speed definition, new in 2021: "Running speed was computed as the magnitude of the Gaussian (bandwidth 0.5 s) smoothed gradient vector of position." (Behavior, p. e2)

- Not stated: filter type, the period for μ and σ, and how immobility is tested within an event. No theta, sleep or unit-count criterion.

- Analysis restrictions: only sessions with good decoding ("75 percentile of decoding error distribution is below 30 cm") were used for replay (p. e4). Significance at Monte-Carlo p < 0.05, where 2019 used 0.01 (p. e4).

- The stimulation electrodes "were not used as part of this study" (p. e2), so there is no online detection here.

## Code

"The data and analysis routines used in this study are available via the Open Science Framework: https://osf.io/smzby. ... Additional code is also available at http://bitbucket.org/kloostermannerflab." (Data and code availability, p. e1). The source inspection covered the OSF inventory and available notebooks; see [source catalog](../sources.md). The code folder was empty and imported detector modules were absent. The lab toolbox (fklab-python-core, read via a GitHub fork) has `detect_mountains` = strict-">" double threshold, then gap join, then drop short, and `compute_envelope` applies the median filter BEFORE Gaussian smoothing (see 25_Michon_2019.md). The original Kloosterman v1.2 routines were also compared with this fork. The missing original caller/version still prevents establishing the paper’s smoothing/detrending order.

## Analysis and interpretation

The <30 cm error entry is the 75th-percentile criterion used to select sessions, not a reported mean or median reconstruction error. Evaluated in 100 ms behavioral windows. Replay uses 500 pooled cross-event surrogates; a separate 500-surrogate direction-bias test also appears.

## Uncertainties

OSF notebooks import unprovided modules, and no dependency lock or event-preprocessing caller is supplied. Original toolbox v1.2 and a later fork differ, so the original smoothing/detrending order remains unresolved.
