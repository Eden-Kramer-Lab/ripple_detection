# Farooq 2019 — Strengthened Temporal Coordination within Pre-existing Sequential Cell Assemblies Supports Trajectory Replay
Source: the extracted text (pdftotext of the Dropbox PDF; Neuron 103, 719–733, 2019; Farooq, Sibille, Liu, Dragoi); title verified: yes
Trigger: MUA (population burst of sorted pyramidal units; ripples only used to split off a robustness subset)

## Method as implemented
Detection criteria (all from STAR Methods, "Detection of frames during slow-wave sleep", p. e2, PDF p. 18, unless noted):

- **State gate (detection): SWS periods from immobility + theta/delta.** "Candidate epochs for sequence analysis, called frames, were detected during slow-wave sleep periods in the sleep box determined based on continuous animal immobility (velocity below 1 cm/s for at least 5 minutes) and low theta/delta ratio (below 2, after Hilbert transform for respective frequencies, 6-12 Hz for theta and 1-4 Hz for delta, and smoothed with a 5 s Gaussian) to exclude epochs of rapid-eye movement sleep."
  - Ratio: theta (6–12 Hz) over delta (1–4 Hz), each via Hilbert transform; absolute threshold 2; 5 s Gaussian smoothing. Not stated: amplitude vs power, whether the 5 s is SD or width, whether smoothing is on the envelopes or the ratio, which LFP channel.
  - Immobility: velocity < 1 cm/s continuously for >= 5 min (a period criterion, not a per-event speed rule).
- **Signal:** "the combined population activity of all putative pyramidal neurons in 1 ms bins was calculated and convolved by a Gaussian kernel of 15 ms." Sorted units ("Only well-isolated putative pyramidal units were used for further analysis", Preprocessing, txt 1467). Whether 15 ms is the SD or the kernel width: not stated.
- **Normalization / threshold / bounds / duration:** "Periods when the population activity exceeded 2 standard deviations above the mean of the population activity, lasted between 100 ms and 800 ms and contained activation of at least 5 distinct neurons were considered as frames". Read literally, the event is the period above 2 SD (bounds at the 2 SD crossings, no extension to the mean), and the 100–800 ms limits apply to that period. Mean/SD computed over: not stated explicitly; the preceding sentence ("For these slow-wave sleep periods, the combined population activity ... was calculated") implies SWS periods (inference).
- **Unit participation:** >= 5 distinct neurons (Methods). The Results say place cells: "Only the frames spanning 100–800 ms and including activation of a minimum of 5 distinct place cells were used for further analysis (Table S2; STAR Methods)" (Results, first section, txt ~143–145). Internal inconsistency: neurons (Methods) vs place cells (Results).
- Merging / close-event rule: not stated. Artifact rejection: not stated. Per-event speed rule: none beyond the SWS immobility gate.

Analysis-only items (not detection):
- **SWR subset (robustness only):** "In addition, sharp-wave ripples were detected using a Hilbert transform and frames containing a ripple event (175-225 Hz) were separated and used to test the robustness of our results." Ripple threshold, smoothing, channel count and duration: not stated. No result using this subset is reported in the text I found.
- "Similar results were obtained when we employed stricter criteria for slow-wave sleep classification (Figure S6A)" (Results, txt 423–425); Fig. S6A legend: "more stringent criteria for sleep detection". The stricter criteria are not specified.
- Later analyses restrict frames further (e.g. template matching "for frames with at least 15 cells", Fig. 4 legend; cell-assembly temporal order "restricted to frames with 5 or more significant cell assemblies", txt 1794). These are analysis restrictions.
- Cross-validation dataset (Grosmark & Buzsáki 2016, EMG-verified SWS) analyzed "using the same data analysis tools" (txt 1820).

## Survey CSV discrepancies
Row 22.
1. **Detection = "SWR, MUA"; Detection Notes = "MUA and SWR".** The paper detects frames from the population rate only. Ripples split off a robustness subset: "frames containing a ripple event (175-225 Hz) were separated and used to test the robustness of our results." Suggest "MUA", with the SWR as a control. The notes should also say "theta/delta ratio", which gates detection (it is in the notes for rows 23 and 26 but missing here).
2. **SWR Low/High Band 175/225:** the band is right, but it describes the control subset, not detection.
3. **Animal Speed 1:** the value is right, but it is a sustained-immobility criterion defining SWS ("velocity below 1 cm/s for at least 5 minutes"), not an event-level speed threshold.

## Package mapping
Tier: B     Needs radiatum: n   Needs theta: y (theta/delta ratio for SWS)   Needs sleep scoring: y (theta/delta < 2 + >= 5 min immobility; user code)

Recipe (`counts`: (n_time, n_pyramidal_units) spike counts in 1 ms bins, fs = 1000):
```python
import numpy as np
from ripple_detection import get_multiunit_population_firing_rate, normalize_signal, multiunit_HSE_detector
from ripple_detection.core import extend_threshold_to_mean

# 1. SWS mask (user code, scipy): theta = |hilbert(bp(lfp, 6, 12))|, delta = |hilbert(bp(lfp, 1, 4))|,
#    ratio smoothed with a 5 s Gaussian; sws = (ratio < 2) & (runs of speed < 1 cm/s lasting >= 300 s)

# 2a. Faithful: frames bounded at the 2 SD crossings
rate = get_multiunit_population_firing_rate(counts, 1000, smoothing_sigma=0.015)
z = normalize_signal(rate, normalization_mask=sws)
frames = np.array(extend_threshold_to_mean(z >= 2, z >= 2, time, minimum_duration=0.100)).reshape(-1, 2)
frames = frames[frames[:, 1] - frames[:, 0] <= 0.800]
#    then keep frames lying inside SWS with >= 5 distinct units spiking (user loop over frames)

# 2b. Nearest one-call version (extends each run to the mean):
counts_sws = counts.astype(float); counts_sws[~sws] = np.nan   # detect and normalize only within SWS
events = multiunit_HSE_detector(time, counts_sws, speed, 1000, speed_threshold=np.inf,
                                zscore_threshold=2.0, minimum_duration=0.100, smoothing_sigma=0.015,
                                maximum_duration=0.800, minimum_active_units=5)
```
(I smoke-tested both call patterns on `simulate_session` data; they run.)

Remaining deviations:
- 2b extends each run to the mean crossing, so its events are wider than the paper's (bounded at 2 SD) and its 800 ms ceiling applies to the extended event. 2a avoids this but needs user code for the unit count and the SWS containment.
- "Exceeded 2 SD" is strict; the package tests `>=`.
- "Gaussian kernel of 15 ms": SD or width unknown; the package takes an SD (`smoothing_sigma`) and truncates at 8 SD.
- Normalization period not stated (SWS inferred). With the NaN approach, smoothing restarts at each SWS boundary, so edge events are clipped and flagged. The paper probably smoothed the continuous train.
- Unit set for the >= 5 count: neurons (Methods) vs place cells (Results). Place-cell classification (peak rate > 1 Hz on track at > 5 cm/s) is user-side.
- SWR subset: `require_overlap(frames, ripples)` would do it, but the ripple threshold is not reported, so the subset is not reproducible exactly (a Hilbert envelope on 175–225 Hz via `filter_ripple_band(lfp, fs, band=(175, 225))` + Kay/Karlsson at a guessed threshold).
- Theta/delta SWS scoring is user code; the package has no theta/delta or sleep-state function.
Smallest package addition (if C): n/a (B). An option on `multiunit_HSE_detector` to bound events at the threshold instead of the mean (e.g. `extend_to="threshold"`) would make the event rule tier A. The SWS gate would still be user code.
