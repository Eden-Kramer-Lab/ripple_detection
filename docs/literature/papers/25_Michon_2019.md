## Method as implemented

Offline ripple detection (used to define candidate replay events):

- "The local field potential recorded from 1-3 tetrodes was downsampled from 32 kHz to 4 kHz and filtered in the ripple frequency band (140-225 Hz). The ripple envelope was computed as the absolute value of the Hilbert-transformed ripple signal, averaged across the recording sites and smoothed with a Gaussian kernel (bandwidth 15 ms). Slow trends in the ripple envelope were removed using a moving median filter (window length 3 s). Finally, start and end times of ripple events were detected when the detrended ripple envelope exceeded a low threshold of m + 0:53s and the maximum envelope exceeded a high threshold of m + 8 3 s. Here, m and s represent the mean and standard deviation of the detrended envelope. Ripple events that were separated by less than 20 ms were merged into one, and events with a duration shorter than 40 ms were excluded." (STAR Methods "Offline ripple detection", p. e3). pdftotext renders μ + 0.5×σ as "m + 0:53s" and μ + 8×σ as "m + 8 3 s".

- Electrodes are in the CA1 pyramidal layer: "Recording electrodes were moved into the hippocampal area CA1 pyramidal cell layer" (p. e2). The filter type is not stated. The period for μ and σ is not stated.

Candidate replay events (the events decoded):

- "A smoothed multi-unit activity (mua) rate histogram (5 ms bin size, Gaussian kernel with 15 ms bandwidth) was computed from all unsorted spikes recorded from the hippocampus with a peak amplitude larger than 60 mA [sic; µV]. The rate was detrended using a moving median filter (window length 3 s). Transient bursts in the detrended mua were defined using a double threshold procedure, where the upper threshold m + 43s determines if a burst occurred and the lower threshold m + 0:53s determines burst start and end time. Bursts that were separated by less than 20 ms were merged into one, and bursts with a duration shorter than 80 ms were excluded. Candidate replay events were defined as mua bursts that overlapped with a ripple event and which occurred while the animal was immobile (speed < 5 cm/s)." (Candidate replay events, p. e4). The rendering is μ + 4σ upper and μ + 0.5σ lower.

- How "occurred while ... immobile" is tested (whole event, endpoints or peak) is not stated.

- No theta or sleep-stage criterion. No unit-count criterion.

Online detection (closed-loop disruption, the manipulation, not the analysed events):

- "Raw signals from 1-3 electrodes were filtered between 135 and 255 Hz using a Chebyshev type-II IIR filter (order = 20) ... Ripple power was summed across electrodes and ripple events were detected when the summed power exceeded f 3 mad(t) + m(t), where m(t) and mad(t) are running estimates of the mean and mean absolute deviation ... f is a multiplier set to a value in the range [5, 13]. Estimates ... exponential moving average filter with span ... [5, 15] seconds. Estimates were not updated during a 50 ms window after each detection." Plus a cortical-electrode veto (−40 ms to 1.5 ms) and a 2 Hz stimulation lock-out (Online ripple detection and disruption, p. e3).

Analysis restrictions: replay significance (Monte-Carlo p < 0.01) (p. e4). Events analysed in the instruction phase and the 2 h delay.

## Code

"Falcon software for closed-loop SWR detection is publicly available at http://www.bitbucket.org/kloostermannerflab. The data and analysis routines used in this study are available on request" (p. e5). The lab's Python toolbox (fklab-python-core; I read a public GitHub fork, KatharinaBracher/fklab-python-core, compared with the original Bitbucket v1.2 source) has:

- `fklab.signals.core.basic_algorithms.detect_mountains(y, x, low, high, allowable_gap, minimum_duration)`: segments where `y > low`, kept if `np.max > high`, then joined across gaps < allowable_gap, then segments shorter than minimum_duration deleted. This is exactly the paper's double-threshold, merge, then drop-short order, with strict ">" on both thresholds.

- `compute_envelope(..., median_filter=..., smooth_options=...)`: mean over channels of |hilbert|, then `apply_median_filter` (a centred rolling median with odd window, `min_periods=1`, subtracted), THEN Gaussian smoothing. That is detrend-then-smooth, the reverse of the paper's wording. Which order the 2019 analysis used is UNKNOWN (fork and version unverified).

- The Gaussian "bandwidth" is the kernel SD (covariance = bandwidth²), so 15 ms bandwidth means smoothing_sigma = 0.015.

- The default "ripple" band is [140, 225] Hz, with a Kaiser-window FIR (`firwin`, 25% transition, 60 dB). This suggests the unstated filter type, but it is an inference from the fork.

## Analysis and interpretation

Real-time

Held-out behavioral reconstruction uses 100 ms windows (Methods, PDF p. 14).

## Uncertainties

The original toolbox version and caller are not pinned. The paper describes smoothing then detrending; the inspected fork detrends then smooths, while original v1.2 has no median detrending in `compute_envelope`.
